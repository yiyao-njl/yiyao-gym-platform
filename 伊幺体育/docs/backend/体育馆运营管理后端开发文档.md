# 体育馆运营管理后端开发文档

## 1. 定位

本端是体育馆运营管理系统的后端中台，目录为 `backend/`。后端统一承接 C 端微信小程序、B 端管理后台以及后续支付、短信、设备等第三方集成。

## 2. 技术栈

- Java 17
- Spring Boot 3.3.5
- Spring Cloud 2023.0.3
- Maven 多模块
- MySQL 8.3
- Redis 7
- RabbitMQ management
- Nacos 2.3.2
- Spring Cloud Gateway
- springdoc-openapi

## 3. 模块说明

- `gym-common`：统一响应、分页、错误码、异常、TraceId、JWT、枚举、共享数据仓库。
- `gym-gateway`：API 网关，端口 8080。
- `gym-auth-service`：认证，端口 8101。
- `gym-user-service`：用户资料和积分，端口 8102。
- `gym-venue-service`：城市、门店、场地、套餐、时段、预约校验，端口 8103。
- `gym-order-service`：购物车、订单、取消、退款申请、预约短锁和场地占用，端口 8104。
- `gym-payment-service`：支付单、支付流水、模拟支付、支付回调，端口 8105。
- `gym-marketing-service`：首页、活动、优惠券，端口 8106。
- `gym-member-service`：会员权益、用户会员，端口 8107。
- `gym-review-service`：评价提交和管理，端口 8108。
- `gym-message-service`：RabbitMQ 拓扑和消息发送，端口 8109。
- `gym-statistics-service`：经营看板和统计，端口 8110。

## 4. 数据源与初始化

- 根目录 `docker-compose.yml` 会挂载 `backend/scripts/init.sql` 初始化 MySQL。
- `init.sql` 当前包含城市、门店、场地、套餐、用户、管理员、订单、支付、活动、优惠券、会员、评价、统计等表和种子数据。
- 当前运行时核心数据访问入口是 `gym-common/src/main/java/com/yiyao/gym/common/data/CommercialDataRepository.java`。
- `DemoDataStore` 仅可作为旧兼容/测试素材，不得作为新增运行时业务数据源。

## 6. 接口与响应规范

统一成功响应：

```json
{
  "code": "SUCCESS",
  "message": "请求成功",
  "data": {},
  "detail": null,
  "traceId": "..."
}
```

分页字段统一为 `pageNo`、`pageSize`、`total`、`totalPages`、`records`。

网关按服务拆分路由，小程序接口使用 `/api/app/**`，后台接口使用 `/api/admin/**`，内部消息接口使用 `/internal/messages/**`。

## 7. 核心业务约束

- MySQL 是业务事实源。
- 场地预约/开场必须使用 Redis 短锁和 MySQL `venue_occupancy` 约束做并发兜底。
- 下单、支付前、支付回调都要校验订单状态、金额和场地可用性。
- 支付回调必须验签、幂等，并记录支付流水。
- 当前 mock 支付只用于开发期，但也必须真实写入 `payment_record` 并推动订单状态变化。
- 订单状态流转应集中在订单服务中维护。
- 后台关键操作必须写操作日志。

## 8. 开发检查清单

1. 新增业务接口时同步更新 Controller、Service、Repository 和网关路由。
2. 新增后台接口时同步更新 `admin-web/src/api/modules.js`。
3. 新增小程序接口时同步更新 `伊幺体育/utils/api.js`。
4. 新增表结构时同步更新 `backend/scripts/init.sql` 和数据库设计文档。
5. 修改订单、支付、退款、场地占用时必须检查幂等、事务和并发冲突。
6. 网关 Path 谓词不要使用 `/api/**/xxx` 这类 `**` 后继续追加路径的写法。
