# 【体育馆运营管理系统后端】支付与订单流程设计文档

## 商用化数据互联同步说明（2026-05-18）

- 订单创建已切向 MySQL：写入 `gym_order`、`gym_order_item` 和 `venue_occupancy`。
- 开发期 `mock-success` 支付通道仍可使用，但必须真实写入 `payment_record` 并更新订单状态。
- 未接真实微信支付商户号前，支付流水和状态流转按可替换开发通道实现。

## 一、支付与订单核心用途/业务定位

- 订单与支付模块是体育馆运营管理系统的交易核心，负责将用户选择的场地、时段、套餐、会员、优惠券等信息转化为可支付、可核销、可退款、可统计的业务凭证。
- 系统必须同时支持预约订单、到店开场订单、购物车合并订单和会员订单。
- 后端是价格、优惠、库存、场地占用、支付结果和退款状态的最终裁决方。

## 二、订单类型与状态

### 2.1 订单类型

- 预约订单：
  - 用户选择未来日期或当天后续时段后创建。
  - 支付成功后正式占用场地。
  - 到达使用时间后可核销或转为使用中。
- 到店开场订单：
  - 用户到店选择当前可用场地或扫码开场后创建。
  - 支付成功后可立即使用。
- 购物车合并订单：
  - 用户勾选多个购物车项统一结算。
  - 一个订单可包含多个场地明细。
- 会员订单：
  - 用户开通或续费会员权益。
  - 支付成功后开通会员，不占用场地。

### 2.2 订单状态

| 状态 | 含义 |
|---|---|
| CREATED | 订单已创建，等待支付 |
| PAYING | 已发起支付，等待支付结果 |
| PAID | 已支付 |
| RESERVED | 预约已生效 |
| IN_USE | 使用中 |
| COMPLETED | 已完成 |
| CANCELLED | 已取消 |
| CLOSED | 超时关闭 |
| REFUNDING | 退款中 |
| REFUNDED | 已退款 |
| REFUND_REJECTED | 退款被拒绝 |

### 2.3 支付状态

| 状态 | 含义 |
|---|---|
| UNPAID | 未支付 |
| PAYING | 支付处理中 |
| PAID | 支付成功 |
| FAILED | 支付失败 |
| CLOSED | 支付关闭 |
| REFUNDING | 退款处理中 |
| REFUNDED | 已退款 |

### 2.4 场地占用状态

| 状态 | 含义 |
|---|---|
| LOCKED | 临时锁定，等待支付 |
| RESERVED | 已预约 |
| IN_USE | 使用中 |
| RELEASED | 已释放 |
| MAINTENANCE | 维护占用 |

## 三、核心业务流程

### 3.1 预约订单流程

- 用户在小程序选择门店、运动类型、场地、日期、开始时间、结束时间和套餐。
- 前端请求后端进行可用性校验。
- 后端校验用户登录态、门店营业状态、场地状态、时段可用性、套餐有效性。
- 后端计算原价、会员折扣、优惠券优惠和最终应付金额。
- 后端创建 Redis 预约锁。
- 后端创建待支付订单和订单明细。
- 前端进入订单确认与支付页面。
- 用户发起微信支付。
- 支付成功回调到支付服务。
- 支付服务验签并记录支付流水。
- 支付服务发送支付成功消息。
- 订单服务消费消息，将订单更新为已支付或预约已生效。
- 预约服务将临时锁转为正式占用。
- 营销服务核销优惠券。
- 会员积分服务发放积分。
- 通知服务发送预约成功或支付成功提醒。

### 3.2 到店开场订单流程

- 用户从首页点击到店开场，进入开场页默认模式。
- 前端选择当前门店和可用场地时段，或扫码识别场地二维码。
- 后端校验当前时间是否处于营业时段，场地是否可用，二维码是否有效。
- 后端创建开场订单并锁定当前可用时段。
- 用户支付后，订单进入已支付或使用中状态。
- 场地状态更新为使用中。
- 使用结束后，订单由系统自动完成或由 B 端员工核销完成。

### 3.3 购物车合并支付流程

- 用户将多个场地时段加入购物车。
- 用户在购物车勾选需要结算的项目。
- 前端请求结算预览。
- 后端逐项校验门店、场地、时段、套餐和价格。
- 如果存在不可结算项目，返回具体原因和可结算项目列表。
- 用户确认后创建合并订单。
- 后端对所有明细加锁，任何一项加锁失败则整个订单创建失败。
- 支付成功后，所有明细场地转为正式占用。

### 3.4 会员订单流程

- 用户进入会员权益页选择开通或续费。
- 后端创建会员订单，计算会员价格。
- 用户支付成功后，会员积分服务开通或延长会员有效期。
- 会员权益变更后清理用户摘要缓存。

### 3.5 支付回调流程

- 微信支付平台请求支付服务回调地址。
- 支付服务验签。
- 支付服务根据第三方交易号和支付单号判断是否已处理。
- 未处理时更新支付流水为支付成功。
- 支付服务发送支付成功消息到 RabbitMQ。
- 订单服务消费消息后更新订单状态。
- 前端订单页通过查询接口获取最新订单状态。

### 3.6 取消订单流程

- 用户可取消未支付订单。
- 后端校验订单属于当前用户且状态允许取消。
- 后端更新订单为已取消。
- 后端释放场地锁。
- 后端释放优惠券占用。
- 已支付订单不能直接取消，应走退款流程。

### 3.7 退款流程

- 用户在订单页申请退款。
- 后端校验订单状态、使用时间、退款规则和用户身份。
- 订单进入退款中或待审核状态。
- 管理员审核通过后，支付服务发起第三方退款。
- 支付服务收到退款成功回调后更新退款流水。
- 支付服务发送退款成功消息。
- 订单服务更新订单为已退款。
- 预约服务释放未使用的场地占用。
- 营销服务按规则恢复或作废优惠券。
- 会员积分服务按规则扣回或冲正积分。

## 四、关键业务校验规则

### 4.1 下单校验

- 用户必须登录。
- 门店必须营业。
- 场地必须启用且可预约。
- 预约日期不得超过后端配置的最大可预约天数。
- 开始时间必须早于结束时间。
- 时段必须落在营业时间内。
- 时段不得与有效占用重叠。
- 套餐必须属于当前场地或场地类型。
- 优惠券必须属于当前用户且未使用、未过期、适用当前订单。

### 4.2 价格计算

- 价格计算顺序建议：
  - 计算场地时长和基础金额。
  - 应用套餐价格规则。
  - 应用会员折扣。
  - 应用优惠券。
  - 得出最终应付金额。
- 所有金额以分为单位。
- 前端传入金额只用于展示比对，后端不得直接信任。

### 4.3 支付校验

- 只有待支付或支付失败可重试的订单允许创建支付。
- 已支付订单再次请求支付时，应返回当前支付状态。
- 支付金额必须等于后端订单应付金额。
- 支付回调金额必须与支付流水金额一致。

### 4.4 退款校验

- 未支付订单不允许退款。
- 已完成且超过退款期限的订单不允许退款。
- 使用中的订单是否允许退款由运营规则决定。
- 已退款订单不得重复退款。
- 退款金额不得超过实付金额。

## 五、状态机要求

- 订单只能按照允许路径流转。
- 常见允许路径：
  - CREATED → PAYING → PAID → RESERVED → IN_USE → COMPLETED。
  - CREATED → CLOSED。
  - CREATED → CANCELLED。
  - PAID → REFUNDING → REFUNDED。
  - REFUNDING → REFUND_REJECTED。
- 禁止路径：
  - CLOSED → PAID。
  - CANCELLED → PAID。
  - REFUNDED → IN_USE。
  - COMPLETED → CREATED。

## 六、异常与边界场景

- 用户支付成功但前端关闭页面：后端通过支付回调更新订单，用户再次进入订单页可看到已支付状态。
- 微信回调延迟：前端查询支付状态时可显示支付处理中，并触发后端主动查单。
- 支付回调重复：支付服务直接返回已处理成功，不重复发消息。
- 订单超时与支付成功同时发生：以后端支付流水和订单状态机判断，已支付订单不得被超时任务关闭。
- 多个购物车项中部分不可用：后端返回不可用项原因，不能静默忽略。

## 七、AI 实现注意事项

- 不要在支付成功前把场地永久占用。
- 不要让订单状态由前端传值决定。
- 不要跳过支付回调验签。
- 不要重复消费支付成功消息导致重复发放会员或积分。
- 不要在订单删除时物理删除支付流水和订单明细。

## 八、当前订单支付落地信息（2026-05-18）

- `gym-order-service` 的 `POST /api/app/orders` 当前支持前端传 `items[]`，字段包括 `venueId`、`storeId`、`packageId`、`bizDate`、`startTime`、`endTime`、`priceCent` 等。
- 创建订单前会使用 Redis 短锁防止同一场地同一时间段并发提交；真正落库时由 MySQL `venue_occupancy` 和重叠校验兜底。
- `CommercialDataRepository.createOrder()` 会创建 `gym_order`、`gym_order_item` 和 `venue_occupancy`。预约订单占用写 `BOOKED`，到店开场写 `USING`。
- `gym-payment-service` 的 `POST /api/app/payments` 会为订单创建 `payment_record`，当前 `paymentMode` 为 `MOCK`，并返回 mock 支付参数。
- `POST /api/app/payments/mock-success` 会把支付流水置为成功，并更新订单支付状态和订单状态；到店开场订单会进入 `IN_USE`，预约订单保留预约使用状态。
- 微信支付、微信云支付和退款回调接口已预留，但当前只返回接收和幂等标识；真实验签、查单、退款回调状态机和 MQ 事件补偿仍需完善。
- 后台当前可通过 `/api/admin/orders`、`/api/admin/payments`、`/api/admin/payments/summary` 查看订单和支付数据。
