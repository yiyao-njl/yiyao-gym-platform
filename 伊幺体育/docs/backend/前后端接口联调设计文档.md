# 【体育馆运营管理系统后端】前后端接口联调设计文档

## 商用化数据互联同步说明（2026-05-18）

- 小程序、管理后台和后端均以网关 `/api/**` 为唯一联调入口。
- 管理后台不再展示运行时假数据；接口失败应显示空态或错误提示。
- 小程序一键登录、下单、支付成功、订单查询和后台统计必须能通过 MySQL 数据互相印证。

## 一、接口联调核心用途/协作定位

- 本文档用于约定 C 端微信小程序、B 端管理后台与后端微服务之间的接口协作规则。
- 接口风格以 REST 风格为主，统一经过 `/api` 前缀和网关转发。
- 前端负责展示、交互、登录引导和基础参数收集；后端负责身份校验、业务规则、价格计算、库存锁定、支付状态和数据持久化。
- 所有接口最终应通过 Swagger/OpenAPI 生成可调试文档，保证前后端可并行开发。
- 当前仓库已有三端基础代码：C 端小程序位于 `伊幺体育/`，B 端管理后台位于 `admin-web/`，后端微服务位于 `backend/`。小程序和后台当前主要使用 mock 数据，后端提供可编译、可启动的接口骨架和部分本地联调用示例逻辑。
- 当前订单与场地占用联调已具备演示闭环：创建订单会校验场地时段，预约订单写入 `BOOKED`，到店开场写入 `USING`，预约开始时间到达后查询侧应返回 `USING`。该闭环只用于接口形态确认，生产必须替换为 Redis/MySQL 持久化方案。

## 二、统一接口规范

### 2.1 请求规范

- 请求地址：
  - C 端接口建议使用 `/api/app` 前缀。
  - B 端接口建议使用 `/api/admin` 前缀。
  - 通用认证接口使用 `/api/auth` 前缀。
- 请求方法：
  - 查询使用 GET。
  - 新增使用 POST。
  - 全量修改使用 PUT。
  - 局部状态变更使用 PATCH。
  - 删除或作废使用 DELETE 或状态变更接口，核心业务数据优先软删除。
- 请求头：
  - 登录后接口必须携带访问 Token。
  - 所有请求建议携带客户端类型、客户端版本和请求追踪标识。
  - 支付回调接口按微信支付要求携带验签相关头信息。

### 2.2 响应规范

- 成功响应字段：
  - `code`：业务状态码。
  - `message`：提示信息。
  - `data`：业务数据。
  - `traceId`：请求追踪标识。
- 失败响应字段：
  - `code`：错误码。
  - `message`：面向前端展示的错误提示。
  - `detail`：可选调试信息，生产环境不暴露内部堆栈。
  - `traceId`：请求追踪标识。
- 分页响应字段：
  - `pageNo`：当前页码。
  - `pageSize`：每页数量。
  - `total`：总记录数。
  - `totalPages`：总页数。
  - `records`：数据列表。

### 2.3 通用错误码

| 错误码 | 含义 | 前端处理建议 |
|---|---|---|
| SUCCESS | 请求成功 | 正常渲染 |
| UNAUTHORIZED | 未登录或登录过期 | 弹出登录提示 |
| FORBIDDEN | 无权限 | 提示权限不足 |
| PARAM_INVALID | 参数错误 | 展示字段提示 |
| RESOURCE_NOT_FOUND | 数据不存在 | 展示空状态或返回上一页 |
| BUSINESS_CONFLICT | 业务冲突 | 展示后端原因 |
| VENUE_UNAVAILABLE | 场地不可用 | 刷新场地状态 |
| ORDER_EXPIRED | 订单已过期 | 返回订单列表 |
| PAYMENT_PROCESSING | 支付处理中 | 继续轮询 |
| PAYMENT_FAILED | 支付失败 | 提供重新支付入口 |
| RATE_LIMITED | 请求过于频繁 | 提示稍后再试 |
| SYSTEM_ERROR | 系统异常 | 提示稍后重试 |

#### 时段状态字段约定

| 字段 | 类型 | 说明 |
|---|---|---|
| `venueId` | string | 场地 ID |
| `bizDate` | string | 业务日期，格式 `yyyy-MM-dd` |
| `startTime` | string | 开始时间，格式 `HH:mm:ss` 或 `HH:mm` |
| `endTime` | string | 结束时间，格式 `HH:mm:ss` 或 `HH:mm` |
| `status` | string | `FREE`、`BOOKED`、`USING`、`MAINTENANCE` 等 |
| `orderId` | string | 占用来源订单，空闲时可为空 |

状态解释：

- `FREE`：可预约或可开场。
- `BOOKED`：预约订单已占用，尚未到开始时间。
- `USING`：到店开场正在使用，或预约订单已到开始时间。
- `MAINTENANCE`：维护或停用，不能下单。

#### 可用性校验请求示例

```json
{
  "venueId": "venue-001",
  "bizDate": "2026-05-18",
  "startTime": "10:00:00",
  "endTime": "11:00:00"
}
```

#### 可用性校验响应示例

```json
{
  "available": true,
  "lockRequired": true,
  "reason": ""
}
```

#### 创建订单请求字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `orderType` | string | 是 | `WALK_IN` 到店开场，`RESERVATION` 预约开场 |
| `couponId` | string | 否 | 使用的优惠券 ID |
| `cartItemIds` | string[] | 否 | 来源购物车项 ID |
| `items` | array | 是 | 下单明细，后端以该明细重新校验时段和价格 |
| `items[].cartItemId` | string | 否 | 来源购物车项 ID |
| `items[].venueId` | string | 是 | 场地 ID |
| `items[].venueName` | string | 否 | 场地名称快照 |
| `items[].storeId` | string | 是 | 门店 ID |
| `items[].packageId` | string | 否 | 套餐 ID |
| `items[].bizDate` | string | 是 | 业务日期，格式 `yyyy-MM-dd` |
| `items[].startTime` | string | 是 | 开始时间，格式 `HH:mm:ss` |
| `items[].endTime` | string | 是 | 结束时间，格式 `HH:mm:ss` |
| `items[].priceCent` | number | 否 | 前端价格快照，最终金额以后端重算为准 |

#### 创建订单请求示例

```json
{
  "orderType": "RESERVATION",
  "couponId": "coupon-001",
  "cartItemIds": ["cart-001"],
  "items": [
    {
      "cartItemId": "cart-001",
      "venueId": "venue-001",
      "venueName": "A1 全场篮球馆",
      "storeId": "store-001",
      "packageId": "pkg-1",
      "bizDate": "2026-05-18",
      "startTime": "10:00:00",
      "endTime": "11:00:00",
      "priceCent": 8800
    }
  ]
}
```

#### 创建订单响应关键字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `orderId` | string | 订单 ID |
| `orderNo` | string | 订单号 |
| `orderType` | string | `WALK_IN` 或 `RESERVATION` |
| `orderStatus` | string | `PAID`、`IN_USE`、`CANCELLED` 等 |
| `paymentStatus` | string | `UNPAID`、`PAYING`、`PAID` 等 |
| `useStatus` | string | `RESERVED`、`IN_USE`、`COMPLETED` 等 |
| `payAmountCent` | number | 应付金额，后端计算结果 |
| `items[].occupyStatus` | string | 创建后占用状态，预约为 `BOOKED`，到店开场为 `USING` |

联调约束：

- 前端不得传入 `orderStatus`、`paymentStatus`、`useStatus` 作为最终状态。
- 后端必须在创建订单时重新校验 `bizDate/startTime/endTime` 是否有效和是否冲突。
- 预约订单开始时间到达后，订单列表、订单详情和场地时段接口均应体现 `IN_USE`/`USING`。
- 订单取消、支付超时关闭、退款完成或管理员释放场地后，场地占用应同步释放。

## 五、联调与验收要求

- Swagger/OpenAPI 中的字段名、类型、是否必填、示例值必须与前端联调保持一致。
- 所有列表接口必须支持空数组返回，不得用异常表示无数据。
- 所有登录后接口在 Token 过期时返回统一错误码，前端不得猜测错误文本。
- 下单、支付、退款、领取优惠券接口必须支持幂等或防重复提交。
- 支付成功页和订单页均应通过后端查询最新状态，不依赖前端本地支付回调结果。
- 小程序当前 `cartValidation.js` 已能组装创建订单请求结构；正式联调时应先接入统一 request 层，再替换 `payment.js` 中的本地 `store.createOrder()` 和 `store.payOrder()`。
- 管理后台当前 `admin-web/src/api/modules.js` 已接入真实接口方法，`src/data/mock.js` 仅保留空结构占位，接口失败不得回落假业务数据。
- `mvn test` 已作为后端基础验证命令；网关路由 Path 不应使用 `**` 后继续追加路径的模式。

## 六、AI 实现注意事项

- 不要让前端传入 `finalAmount` 后直接入库，金额必须后端重算。
- 不要让前端传入 `orderStatus` 或 `paymentStatus` 直接修改状态。
- 不要把不同页面需要的数据强行放进一个无限膨胀的接口，首页聚合接口除外。
- 不要在接口中返回数据库内部字段、删除标记、密码哈希或第三方密钥。
- 不要让 B 端接口缺少门店数据权限过滤。

## 七、当前接口工具与联调信息（2026-05-18）

- 小程序请求工具为 `伊幺体育/utils/request.js`，默认网关地址 `http://localhost:8080`，可通过 storage key `gym-api-base-url` 覆盖；`utils/api.js` 已封装认证、首页、城市、门店、场地、预约校验、订单、支付和订单列表。
- 管理后台请求工具为 `admin-web/src/api/request.js`，baseURL 为 `/api`，由 Vite 或 nginx 代理到网关；`src/api/modules.js` 已封装后台登录、看板、门店、场地、订单、支付、用户会员、营销、评价、系统日志等接口。
- 后端网关当前以 `/api/**` 为三端唯一入口，后台 `/api/admin/**` 和小程序 `/api/app/**` 均通过 `gym-gateway` 转发。
- 当前已落地的关键联调链路：小程序登录 `/api/auth/app/wechat-login`，场地预约校验 `/api/app/reservations/check`，创建订单 `/api/app/orders`，创建支付 `/api/app/payments`，mock 支付成功 `/api/app/payments/mock-success`，后台看板 `/api/admin/statistics/dashboard`。
- 支付回调预留接口包括 `/api/app/payments/wechat/callback`、`/api/app/payments/wechat/cloud-callback` 和 `/api/app/payments/refund/callback`，当前返回幂等接收结果，真实验签与微信查单仍需补齐。
- 后台接口失败时不得回落 `src/data/mock.js` 假数据；小程序 `mockData.js` 只作为 UI 兜底素材，不作为业务事实源。
