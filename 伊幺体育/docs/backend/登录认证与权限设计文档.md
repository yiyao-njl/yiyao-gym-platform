# 【体育馆运营管理系统后端】登录认证与权限设计文档

## 商用化数据互联同步说明（2026-05-18）

- 小程序一键登录接口 `/api/auth/app/wechat-login` 已作为用户 upsert 和 JWT 签发入口。
- 管理员账号来自 MySQL `admin_account`，角色包括 `SUPER_ADMIN`、`MANAGER`、`STAFF`。
- 开发期默认密码为 `admin123`，后续服务器部署必须替换为 BCrypt 密码和环境级 JWT 密钥。

## 一、登录认证核心用途/安全定位

- 登录认证模块用于确认 C 端用户和 B 端管理员身份，并向各后端服务提供统一可信的身份上下文。
- 系统采用 Spring Security + JWT 实现无状态接口认证，使用 Redis 保存刷新 Token、登录态版本、验证码、Token 黑名单和临时会话数据。
- C 端以微信授权登录为主，B 端以账号密码登录为主。两类登录入口必须分开设计，但统一输出后端 Token 和用户身份结构。
- 权限控制以角色和权限点为基础，同时结合门店数据权限，保证店长和员工只能管理授权范围内的数据。

## 二、主要功能详情

### 2.1 C 端微信小程序登录

- 登录流程：
  - 小程序调用微信登录能力获取临时登录凭证。
  - 前端将临时登录凭证提交给后端认证服务。
  - 后端调用微信接口换取用户唯一身份标识。
  - 后端根据微信身份标识查询或创建用户。
  - 后端签发访问 Token 和刷新 Token，并返回用户基础资料。
- 登录结果：
  - 返回用户编号、昵称、头像、手机号绑定状态、会员等级、积分/XX 币摘要、优惠券数量。
  - 未绑定手机号时，仍可浏览公开内容，但涉及支付、退款或必要实名场景时应引导绑定。
- 安全要求：
  - 前端不得直接保存微信敏感密钥。
  - 后端不得把微信会话密钥返回给前端。
  - 同一用户多端登录时，可允许共存，也可使用登录态版本控制旧 Token 失效。

### 2.2 B 端账号密码登录

- 登录流程：
  - 管理员输入账号、密码和可选验证码。
  - 后端根据账号查询管理员信息。
  - 使用 BCrypt 校验密码。
  - 校验账号状态、角色状态和门店授权状态。
  - 登录成功后签发访问 Token 和刷新 Token。
- 管理员信息：
  - 包含管理员编号、账号、姓名、手机号、角色列表、权限点列表、所属门店列表、数据权限范围。
- 安全要求：
  - 密码连续错误达到阈值后应临时锁定账号或要求验证码。
  - 禁用、离职或删除的管理员不得登录。
  - 管理员退出登录后当前刷新 Token 必须失效。

### 2.3 JWT Token 设计

- 访问 Token：
  - 用于接口鉴权。
  - 有效期较短，建议 2 小时以内。
  - 携带用户类型、用户编号、角色摘要、登录态版本和签发时间。
- 刷新 Token：
  - 用于换取新的访问 Token。
  - 有效期较长，建议 7 至 30 天。
  - 必须保存在 Redis 中，退出登录或异常风险时可主动删除。
- Token 携带方式：
  - 前端通过请求头携带访问 Token。
  - 文件上传、特殊下载等场景仍应优先使用请求头，不建议放在 URL 参数中。
- Token 失效：
  - 过期、签名错误、黑名单命中、登录态版本不一致均视为无效。

### 2.4 刷新与退出登录

- 刷新 Token：
  - 当前访问 Token 过期后，前端使用刷新 Token 请求新的访问 Token。
  - 刷新成功后可同时续期刷新 Token。
  - 刷新失败时前端必须回到登录流程。
- 退出登录：
  - 前端调用退出接口。
  - 后端删除刷新 Token，并将当前访问 Token 加入短期黑名单。
  - 前端清理本地 Token、用户信息和页面登录态。
- 登录过期：
  - 后端返回统一错误码。
  - 前端弹出登录提示，登录完成后回到原页面继续原操作。

### 2.5 角色与权限模型

- 默认角色：
  - 超级管理员：拥有全局配置、所有门店和所有业务数据管理权限。
  - 店长：拥有所属门店的场地、订单、活动、员工和统计管理权限。
  - 员工：拥有被分配的日常操作权限，例如订单核销、扫码开场、订单查看。
  - 普通用户：拥有 C 端浏览、下单、支付、评价、优惠券和个人资料权限。
- 权限点建议：
  - 用户管理查看。
  - 门店配置管理。
  - 场地配置管理。
  - 订单查看。
  - 订单状态处理。
  - 退款审核。
  - 优惠券管理。
  - 活动管理。
  - 会员管理。
  - 评价管理。
  - 统计查看。
  - 系统日志查看。
- 数据权限：
  - 超级管理员可访问全部门店。
  - 店长默认访问所属门店。
  - 员工默认访问被授权门店。
  - 普通用户仅能访问自己的个人数据。

## 四、异常与边界场景

- 微信登录凭证过期时，后端返回登录失败，前端重新调用微信登录。
- 用户被禁用时，不允许登录，也不允许继续调用业务接口。
- 管理员角色被调整后，旧 Token 的权限不能长期保留，应通过登录态版本或权限版本使其及时刷新。
- 用户在支付过程中 Token 过期时，前端可刷新 Token 后继续查询支付状态，但不能重复创建订单。
- 多次点击登录、支付、领取优惠券等按钮时，后端需通过防重复机制保证幂等。

## 五、AI 实现注意事项

- 不要在 JWT 中放入密码、手机号全量、微信会话密钥等敏感信息。
- 不要使用明文、MD5 或 SHA 单次哈希保存密码，必须使用 BCrypt。
- 不要只在前端控制 B 端菜单权限，后端接口必须再次校验。
- 不要让普通用户通过修改用户编号访问他人订单或优惠券。
- 不要为开发方便保留万能 Token、固定验证码或免登录后门。
