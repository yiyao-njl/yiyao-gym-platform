# 体育馆运营管理小程序前端开发文档

## 1. 定位

本端是体育馆运营管理系统的 C 端微信小程序，目录为 `伊幺体育/`。当前技术栈为原生微信小程序，负责用户侧浏览门店、选择场地、到店开场、预约开场、购物车、支付、订单、会员、优惠券、活动和个人中心。

## 2. 技术与配置

- `app.json` 启用 `cloud: true`，使用自定义导航 `navigationStyle: "custom"`。
- `app.js` 初始化云环境 `cloud1-6g1zde6bb1996733`。
- `project.config.json` 中 AppID 为 `wxd13b3906dfa6d35b`，基础库版本为 `3.5.8`。
- 底部 TabBar 为：首页、开场、订单、我的。
- 编辑 `app.json` 时必须保持 UTF-8 without BOM。

## 3. 页面结构

当前页面包括：

- `index`：首页和核心入口。
- `open`：到店开场/预约开场主流程。
- `venue`：场地详情、套餐和自定义时间选择。
- `cart`、`payment`：购物车、订单确认和模拟支付。
- `orders`、`orderDetail`：订单列表和订单详情。
- `mine`、`login`、`phoneLogin`、`accountManage`、`switchAccount`、`logout`：个人中心与登录账号。
- `city`、`store`、`member`、`coupon`、`activity`、`profileEdit`、`expDetail`：配套业务页面。

新增页面必须同步加入 `app.json` 的 `pages` 数组。

## 4. 工具模块

- `utils/request.js`：后端请求封装，默认 `http://localhost:8080`，可用 storage key `gym-api-base-url` 覆盖。
- `utils/api.js`：小程序 API 聚合，包含登录、首页、城市、门店、场地、预约校验、订单、支付等接口。
- `utils/store.js`：本地状态管理，storage key 为 `gym-front-state`。
- `utils/timeSlots.js`：营业时间、时间刻度、占用状态和跨 24 点规则。
- `utils/cartValidation.js`：购物车校验、价格试算、优惠计算和后端订单请求组装。
- `utils/mockData.js`：仅作为 UI 兜底素材，新增业务不得以它作为事实源。

## 5. 后端接入规则

- 小程序接口统一通过网关 `/api/**` 访问。
- 一键登录调用 `/api/auth/app/wechat-login`，后端负责用户 upsert、手机号绑定和 JWT 签发。
- 请求头由 `utils/request.js` 注入 `Authorization` 和 `X-Client-Type: wechat-mini`。
- 首页、门店、场地、预约校验、订单、支付、会员、优惠券、活动都应逐步以 MySQL 后端结果为准。
- 本地 storage 只保存 token、当前门店、临时 UI 状态和未提交草稿。

## 6. 核心业务约束

- 到店开场只展示今天当前时间之后可用时段。
- 预约开场显示未来 7 天日期，并按所选日期计算场地状态。
- 时间刻度和状态判断必须复用 `timeSlots.js`。
- 购物车项包含 `quantity` 和 `checked`，数量影响角标、价格、优惠、支付和订单展示。
- 支付、订单状态、场地占用和优惠结果最终以后端为准。
- 真实联调后，前端本地 `venueOccupations` 只能作为离线兜底或过渡逻辑，不应覆盖后端结果。

## 7. 开发检查清单

1. 修改页面后检查 `app.json` 注册和 TabBar 路径。
2. 修改状态结构后检查旧 `gym-front-state` 兼容。
3. 修改时间轴后同步检查 `open`、`venue`、`cartValidation.js` 和订单展示。
4. 修改下单支付后同步检查后端订单请求字段：`orderType`、`items[].venueId`、`bizDate`、`startTime`、`endTime`、`priceCent`。
5. 联调前先清理微信开发者工具缓存，确认 `gym-api-base-url` 指向当前网关。
